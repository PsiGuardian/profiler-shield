## დამატებითი დაცვა

დაცვის მექანიზმები შესაბამის პარამეტრებთან ერთადაა დაჯგუფებული. გამორთული ფუნქციები ჩამუქებულია და მათი მნიშვნელობები ინახება.

Guardian აკონტროლებს პროფაილერსა და გამართვის პანელს. საჭიროა ნებადართული ადმინისტრატორის ან დეველოპერის ანგარიში. MFA, განრიგი, JIT, ქსელური შეზღუდვები და სრული ბლოკირება კვლავ მოქმედებს. ფარული რეჟიმი ამ შემოწმებებს არ ცვლის.


```text
POST ∧ CSRF ∧ role=admin ∧ password
```

ჩართეთ განრიგი და აირჩიეთ დღეები. დასაწყისის დრო შედის ინტერვალში, დასრულების დრო — არა. ადგილობრივ დროს შენახული სარტყელი განსაზღვრავს. შუაღამის გადამკვეთი ინტერვალები დაუშვებელია. არასამუშაო საათებში პორტალის დამალვა საგანგებო დისტანციურ წვდომასაც ზღუდავს; შეინარჩუნეთ ადგილობრივი აღდგენის წვდომა.

უმოქმედობის ვადას, სესიის მაქსიმალურ ვადასა და მოწყობილობის დამახსოვრებას სხვადასხვა დანიშნულება აქვს. დამახსოვრება განრიგსა და JIT-ს არ აუქმებს. გაუქმება სესიებს სერვერზე წყვეტს. ქმედებების აღსარიცხად გამოიყენეთ ინდივიდუალური ანგარიშები.

JIT მოითხოვს დროებითი ფანჯრის გააქტიურებას ავტორიზებული სესიიდან. საგანგებო წვდომას სჭირდება პაროლი, ერთჯერადი კოდი და მიზეზი. ის სრულ ბლოკირებას არ აუქმებს. თუ პორტალი მიუწვდომელია, საჭიროა ადგილობრივი ბრძანებები.

IP სია იღებს IPv4, IPv6 მისამართებსა და CIDR ქსელებს. ჩართვამდე შეამოწმეთ Symfony-ის სანდო პროქსები. უსაფრთხო ქუქიებისთვის გამოიყენეთ HTTPS. Guardian არ ასწორებს საჯაროდ გახსნილ ვებსერვერს ან მონაცემთა ბაზას.

დონე და შენახვის ვადა განსაზღვრავს მოვლენებს, მაქსიმუმ 5000 ჩანაწერს. გვერდის შეცვლამდე გაფილტრეთ ტიპითა და ანგარიშით. გაფრთხილებები რიგში თავსდება; გამართეთ მათი ტრანსპორტი და გაგზავნა. ჰეშების ადგილობრივი ჯაჭვი დაზიანებულ სერვერზე მთლიანობას ვერ უზრუნველყოფს.

დააყენეთ მინიმალური სიგრძე და სავალდებულო კატეგორიები. ანგარიშის შექმნისას ნაჩვენებია შენახული მოთხოვნები. ცვლილება ახალ პაროლებზე მოქმედებს; არსებულებისთვის მონიშნეთ სავალდებულო განახლება. Guardian ირჩევს Argon2id-ს, თუ PHP უზრუნველყოფს, სხვაგვარად — bcrypt-ს.

გაფილტრეთ შენახული მოვლენები ტიპითა და ანგარიშით. ახალი მოვლენები პირველია, გვერდზე 50 ჩანაწერით. გადახვევა შემდეგ გვერდს არ ტვირთავს.

## გარემო


```dotenv
GUARDIAN_LOGIN_PATH=/internal/<random-48-hex>
GUARDIAN_ENCRYPTION_KEY=<64-hex>
GUARDIAN_STORAGE_DIR=<private-directory>
GUARDIAN_COLLECTION_BRIDGE=0
GUARDIAN_DEBUG_ERRORS_FOR_AUTHENTICATED=0
GUARDIAN_SHOW_PHP_VERSION=0
```


პროქსი უზრუნველყოფს TLS-ს, ნორმალიზაციასა და დიდი ტრაფიკისგან დაცვას. კარიბჭე დიაგნოსტიკას ამოწმებს მარშრუტიზაციამდე; ბიზნესმარშრუტები ანგარიშებსა და სესიებს არ კითხულობს. Guardian-ის იდენტობა Symfony-ისგან განცალკევებულია. პირადი საცავი და გასაღები ერთად დააკოპირეთ საჯარო საქაღალდის გარეთ. დაზიანებულმა PHP-მ ან ჰოსტმა შეიძლება ორივე გაამჟღავნოს. საცავი ერთ ჰოსტზეა გათვლილი. გაშვების, ქეშის ან პროქსის შეცდომამ შეიძლება მთელი აპლიკაცია დააზიანოს.

საცავი და გასაღები ერთად შეინახეთ და აღდგენა გამოსცადეთ. დაკარგული გასაღები ავტომატურად არ იქმნება. წაშლის შემდეგ პროფაილერი მხოლოდ დახურულ გარემოში შეამოწმეთ. საწარმოო გარემო: APP_DEBUG=0, WebProfilerBundle და შეგროვება გამორთულია. აუდიტის ადგილობრივი ჯაჭვი გატეხილი ჰოსტის მთლიანობას ვერ ამტკიცებს.

## აღდგენა და შემოწმება

აცარიელებს IP სიას და თიშავს განრიგს, JIT-სა და დისტანციურ საგანგებო წვდომას. ავთენტიფიკაცია, MFA, საერთო ბლოკი და შესვლის ბლოკები რჩება. აღდგენის შემდეგ პანელში თავიდან დააყენეთ საჭირო შეზღუდვები.

on კეტავს დიაგნოსტიკას და შლის ყველა სესიას; ბიზნესგვერდები მუშაობს. off ხსნის მხოლოდ საერთო ბლოკს: საჭიროა ხელახალი შესვლა და სხვა პოლიტიკები ძალაში რჩება.


```bash
php bin/console guardian:policy:reset --env=dev
php bin/console guardian:lockdown on --env=dev
php bin/console guardian:doctor --env=dev
```
